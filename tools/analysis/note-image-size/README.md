# 笔记长图体积粗估

当前职责以 [ARCHITECTURE.md](../../../../doc/ARCHITECTURE.md) 为准。本目录是离线校准工具，不参与应用运行，也不增加应用依赖。

`NoteImageSizeEstimate` 在已有排版过程中累计实际输出文字（排除 Markdown 标记）的字符类型、字号、标题粗体，以及已读取图片的编码字节数、格式、原始尺寸和最终绘制尺寸。文字使用固定字体下的经验系数；图片用编码字节/像素与缩放比例的对数回归估算目标字节/像素；背景使用少量固定开销。每张图片只做常数次运算，不读取像素。冻结 artifact 携带两个最终数字，预览直接显示。

运行时不再光栅化、扫描、抽样或预压缩整张长图；旧的像素特征、预测 STA 和校准模型已移除。工作量与正文字符及图片出现次数相关，不随图片像素数扫描增长。实际预览排版、图片读取/解码、最终导出仍有原来的成本。

## 精度边界

目标是常见笔记约 50% 的相对误差，而非每个输入的硬保证。小于 1 MiB 仍显示“小于1m”，其余取整显示“约xm”。大图可能有更大绝对误差。相同尺寸、源文件大小和格式的图片仍可能有完全不同的目标压缩体积；尤其 JPEG 转 PNG、极端噪声、渐变、少色截图以及大幅缩放。GIF/TIFF 或没有源编码信息的内存图片使用宽泛的混合图片先验，不能宣称与 PNG/JPEG 元数据路线同等准确。

测试同时输出原始预测与真实大小，不把整数显示容差说成原始百分比精度。文字系数以此前 Windows 中文长文、代码样例为校准依据；其余文本和图文用真实 WPF/WIC 导出验证。

## 离线图片校准

```sh
python tools/analysis/note-image-size/calibrate.py
```

需要 Python、Pillow、NumPy、scikit-learn，以及 DejaVu Sans 字体。脚本生成纯色、渐变、纹理、噪声、形状、文字截图及 scikit-learn 内置的两张示例照片；源编码为 PNG 或质量 82/90/98 JPEG，目标为质量 90 JPEG 与 RGB/Sub PNG。缩放覆盖 0.25/0.5/1/1.5。种子 17/23 拟合，37 检查，输出 `metadata-images.json` 与系数/误差报告。照片来源和生成器在两组之间仍有重叠，不能把该检查组称为独立照片泛化验证。离线校准生成真实编码标签，应用预览路径不编码。

`tests/PaperTodo.LifecycleChecks/NoteImageSizeChecks.cs` 用真正的 WPF 排版和两个实际编码器验证整篇结果。统计开销单独用 58,000 字符和 100 次图片元数据计算计时，包含字符遍历、图片公式与最终求和；不把读取 artifact 两个数字的时间冒充估算总成本。此计时不包含预览排版，也不与旧版含光栅化计时计算严格机器加速比。

修改字体、输出比例、JPG 质量或 PNG 过滤/编码方式时，应重新检查系数。已有失败路线与取舍见 Decisions D-066。
