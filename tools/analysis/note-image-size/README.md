# 笔记长图体积粗估

当前职责以 [ARCHITECTURE.md](../../../../doc/ARCHITECTURE.md) 为准。本目录是离线校准工具，不参与应用运行，也不增加应用依赖。

`NoteImageSizeEstimate` 在已有排版过程中累计实际输出文字（排除 Markdown 标记）的字符类型、字号、标题粗体，以及已读取图片的编码字节数、格式、原始尺寸和最终绘制尺寸。文字使用固定字体下的经验系数；图片用编码字节/像素与缩放比例的对数回归估算目标字节/像素；背景使用少量固定开销。每张图片只做常数次运算，不读取像素。冻结 artifact 携带两个最终数字，预览直接显示。

运行时不再光栅化、扫描、抽样或预压缩整张长图；旧的像素特征、预测 STA 和校准模型已移除。工作量与正文字符及图片出现次数相关，不随图片像素数扫描增长。实际预览排版、图片读取/解码、最终导出仍有原来的成本。

## 精度边界

目标是常见笔记约 50% 的相对误差，而非每个输入的硬保证。小于 1 MiB 仍显示“小于1m”，其余取整显示“约xm”。大图可能有更大绝对误差。相同尺寸、源文件大小和格式的图片仍可能有完全不同的目标压缩体积；尤其 JPEG 转 PNG、极端噪声、渐变、少色截图以及大幅缩放。GIF/TIFF 或没有源编码信息的内存图片使用宽泛的混合图片先验，不能宣称与 PNG/JPEG 元数据路线同等准确。

测试同时输出原始预测与真实大小，不把整数显示容差说成原始百分比精度。文字系数以此前 Windows 中文长文、代码样例为校准依据；其余文本和图文用真实 WPF/WIC 导出验证。

## 离线图片校准

```sh
python tools/analysis/note-image-size/calibrate.py
```

需要 Python、Pillow、NumPy、scikit-learn，以及 DejaVu Sans 字体。脚本生成纯色、渐变、纹理、噪声、形状、文字截图及 scikit-learn 内置的两张示例照片；源编码为 PNG 或质量 82/90/98 JPEG，目标为质量 90 JPEG 与 RGB/Sub PNG。缩放覆盖 0.25/0.5/1/1.5。种子 17/23 拟合，37 检查，输出 `metadata-images.json` 与系数/误差报告。照片来源和生成器在两组之间仍有重叠，不能把该检查组称为独立照片泛化验证。离线校准生成真实编码标签，应用预览路径不编码。

`tests/PaperTodo.LifecycleChecks/NoteImageSizeChecks.cs` 用真正的 WPF 排版和两个实际编码器验证整篇结果。统计开销单独用 58,000 字符和 100 次图片元数据计算计时，包含字符遍历、图片公式与最终求和；不把读取 artifact 两个数字的时间冒充估算总成本。此计时不包含预览排版，也不与旧版含光栅化计时计算严格机器加速比。

修改字体、输出比例、JPG 质量或 PNG 过滤/编码方式时，应重新检查系数。已有失败路线与取舍见 Decisions D-066。

## JPEG 文件头校准

`NoteImageJpegInfo` 按 JPEG T.81 的 DQT/SOF/SOS 标记读取首分量使用的量化表均值、亮度/色度采样比例和首个扫描头之后的字节数。仅检查最多 128 个头标记，APP/ICC 段按长度直接跳过；遇到扫描数据立即停止，不读取图像像素或熵编码正文。缺失或不能使用的头信息继续走原有粗估，不阻止导出。没有新增持久化字段或运行时依赖。

新增回归按源数据密度、量化均值、采样比例和缩放比例计算 JPG/PNG；文字和 PNG 原图的后续细分见下文。只在已校准的量化/采样范围内启用；接近纯色编码下限的 JPEG→PNG 保留原粗估。PNG 拟合按实际体积加权，降低几 KB 小图在相对误差目标中的权重，仍报告未经显示取整的真实误差。

```sh
python tools/analysis/note-image-size/jpeg_calibrate.py
# 可用 --data 复用上次生成的 jpeg-corpus.json；--photo-dir 可重新编码独立照片。
```

训练：种子 17/23 的 14 个合成场景与 china/flower 两张照片；调参检查：种子 37 的 7 个合成场景，照片不重复进入此组。独立照片为 OpenCV 的 baboon/building/fruits 和 Pillow 的 hopper，源文件路径与 blob SHA、192 组编码测量在 `jpeg-validation.json`；这四张图不参与拟合。每张图有多种压缩/缩放变体，因此 192 组测量不等于 192 张独立照片，且 Pillow 的图像校准不能替代 WPF/WIC 整篇导出验收。

本轮独立照片 JPG 中位相对误差由约 35.1% 降至 18.2%，PNG 中位数约 18.7%→19.0%，PNG 第 90 百分位由约 43.7% 降至 31.1%。改善侧重 JPG 与 PNG 的较大偏差，不表示每张图都会更准。Windows 检查另外覆盖真实图片编码、完整文章、不同量化参数、无效/截断头及附加元数据不影响预测；计时包括 100 次文件头解析及两种体积计算；当前混合基准为 50 次 JPEG 和 50 次 PNG。

格式依据：[ITU-T T.81 B.2](https://www.w3.org/Graphics/JPEG/itu-t81.pdf)。

## PNG 文件头校准

`NoteImagePngInfo` 只读取 IHDR 的颜色类型/位深、PLTE 长度、tRNS 标记及各 IDAT 的长度，按长度跳过块正文，不解压缩、不读取像素，也不验证已由图片解码器处理的 CRC。附加文本/ICC 信息不再被当作图像复杂度；块数超过 1024、信息缺失或动画 PNG 使用原粗估，不妨碍正常导出。

非隔行、位深不超过 8 的不透明灰度/调色板图，以及 RGBA 图使用颜色模式、位深和调色板大小细分的公式。普通 RGB 新拟合没有稳定收益，保留旧公式；灰度带透明通道、tRNS 色键透明、16 位和隔行图没有足够校准依据，也保留旧公式。透明标记无法说明实际透明面积，RGBA→JPG 取原式与新式的几何平均，避免只凭有透明通道就过度下调。

```sh
python tools/analysis/note-image-size/png_calibrate.py
# --data cached-png-corpus.json 复用测量；--photo-dir source-jpegs 重测独立照片。
```

训练与合成验证沿用 JPEG 校准的 14+2 个训练场景、7 个验证场景。各自生成 RGB、8 位灰度、阈值黑白、抖动黑白、4/16/256 色调色板、全不透明 RGBA、渐变透明 RGBA，源压缩级别 1/6/9，输出缩放 0.25/0.5/1/1.5；透明图先在白底合成，再以 JPEG90 或 RGB/Sub/zlib6 PNG 编码。脚本仅离线使用，运行时没有这些转换或依赖。

`png-validation.json` 记录 4 张未参与拟合的照片及 432 组格式/缩放组合的原始大小（每种输出格式各 432 个），并保留来源与 blob SHA。冻结模型后，JPG 中位相对误差 51.0%→22.5%，PNG 36.9%→20.8%；不是 432 张独立照片，也不表示逐张改善。Windows 新回归暴露了抖动黑白→JPG 的低估，因此补充 Floyd–Steinberg 黑白训练样本，并只替换 1 位灰度→JPG 的密度/缩放公式；这项 Windows 用例从发现问题起作为回归保留，不能再称为未见过的独立验证。Windows 另用 WPF 实际编码的灰度、16 色、透明、黑白图片，在 50%/100% 栏宽下验证整篇笔记。小图依然按原 `max(0.5 MiB, 实际大小×50%)` 容差检查，同时输出未取整的百分比误差。

格式依据：[W3C PNG 规范](https://www.w3.org/TR/png/)。

## 文字与装饰校准

`text-controls.json` 保存 Windows/WPF 的八组控制实验原始大小；`text_calibrate.py` 可重算系数。中日韩字符不再共用一个系数：汉字保留原值，日文假名、韩文字母及正文窄字符分别由独立控制段落校准，再适度取整。英文正文与等宽代码分开，行内格式使用真正绘制的字号/粗体/代码字体；仍只遍历一次实际文字，不读取字形或像素。引用框和复选框按同文案对照的体积差记录少量固定开销，不扫描装饰区域。

保留既有中英文与代码回归，另外四篇 `new-*-heldout` 文本不进入系数计算；其中韩文在细分前越过旧误差门槛，这个发现已用于确定修正方向，最终结果应表述为保留样例对照而非完全独立盲测。校准控制组输出原始大小、不参与精度门槛；原有用例及新回归的误差容差不变。扩展到 42 篇笔记后仅将 `image-export` 子进程的真实编码时限由 30 秒调至 90 秒，其他生命周期时限及预测性能门槛不变。
