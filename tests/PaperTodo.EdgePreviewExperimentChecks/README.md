[首次四类场景对照运行](https://github.com/snownico0722/PaperTodo/actions/runs/34623945732) 的完整旧记录见该提交下本文件和 `edge-preview-avalonedit-results` artifact。结论是短文更早就绪，但密集长行会明显阻塞动画，不能由“正文十万字符解析很快”推出“直接嵌入整个正文控件也很快”。

前一轮 `34623523468` 的既有 MarkdownEditing 像素检查曾失败，随后未修改该断言或正文实现，原版对照与候选均通过；此未稳定复现的记录仍保留，不宣称已修复。

能确认主要成本在排版，而非解析。第二次内部重建的具体触发原因尚未进一步隔离；这不是已证明的 AvalonEdit 库缺陷，也不是主正文已被修复的结论。

## 当前组合版

- 行内语法识别直接调用正文已有的 `MarkdownSemanticSnapshot.Parse`。删除预览的递归行内正则解析；轻量适配器将已识别的范围转为纯数据样式段，支持嵌套强调、转义、链接和既有受限 HTML 样式。图片继续为占位，不读取图片存储。
- 复用 #243 已有的 `MarkdownEdgePreviewParagraph`：TextFormatter 按可见折行分批准备，绘制结果和可见链接区域保留到该次预览结束，重新布局/重绘不重新格式化文字。不是新建第三套文字排版器。
- 保留 main 的轻量尺寸估算，不采用 #243 的同步逐短行 WPF 精确测量。尺寸和显示继续共用 16 块/6000 字符预算；保留取消旧工作、一次发布和 #244 的首次正文/有序序号处理。

共享的是语法识别实现，不是主正文的可编辑 TextDocument，也不是整篇笔记已有的语义快照。当前按受限行内片段编译；块级预览仍沿用现有适配逻辑。跨行语法、引用定义和完整正文外观一致性不在本轮宣称解决的范围。尺寸仍是 main 的轻量估算，不承诺像素级贴合。
