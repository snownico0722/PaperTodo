# 边缘预览预热检查

本功能沿用既有受限文字预览、#249 的共享 STA 排版与相同的内容分类规则。正式职责和 ownership 见 [ARCHITECTURE](../../doc/ARCHITECTURE.md) 的「内置笔记的边缘预览」。本文件只记录可执行检查和历史实验口径，不是另一份架构或发布批准。

## 当前规则

只为存活、可见、实际属于边缘胶囊队列的内置 Markdown Note 排队；要求胶囊模式、边缘胶囊及悬停预览开启。分类只看前 16 块 / 6000 字符的有界摘要，满足任意一条：

- 总源字符数 >400；
- 总源字符数 >200 且样式/链接覆盖字符 >100；
- 总源字符数 >200 且样式/链接片段 >3。

所有比较都是严格大于。总源字符数取摘要各行长度之和，不额外计入换行；样式覆盖和片段按去掉语法标记后的语义内容计算，不把增强模式的 `**`、标签或链接目标重复当成样式片段。嵌套样式不会重复累计同一个字符。围栏内非空正文行按代码样式计数。Off 模式只启用总字符数规则。当前仍是有限预览适配，不扩展块级语义合同。

启动恢复结束和后续入队、纸片形态或内容变化只提交最新的延后读取请求；包括分类在内的准备工作在共享 **500ms 一次性合并延迟**之后执行。没有新的启动计时器、鼠标邻居预测或产品预解析队列。WPF 的 ContextIdle 是低优先级，不代表系统 CPU 已完全空闲，也不保证不可抢占的单次工作段不会影响呈现。

每个合格来源最多保留一份当前不可变绘制结果（artifact），不保留隐藏卡片或 WPF 正文树，不按固定张数淘汰。正式悬停优先，被打断但仍有效的请求保留并重新排队；新请求不能被旧任务的完成回调删除，也不能绕过新的合并延迟。永久不符合条件、失败或暂时不能承载的目标不持续轮询，后续正常生命周期事件可以重新提交。

artifact 留在缓存中，每次挂载创建自己的绘制面和原生链接交互元素，不再借出或归还正文控件。内容版本、摘要、正文宽度、DPI、字体、显示模式和资源不符时拒绝复用；当前卡片上限内的不同高度按实际 viewport 裁剪。关闭、移出队列或清空缓存后，旧任务不能把已撤销的结果重新存回。资源变化直接丢弃当前预热，由后续正常请求恢复，不自动轮询重试。启动或修改后立即打开仍可未命中，并走正常分批准备。

## 当前可执行检查

默认 EdgePreview suite 显式执行 artifact 链接检查，不依靠未引用字段的静态初始化。原生链接覆盖独立命中、背景穿透、裁剪、按下/释放、Space、Enter、焦点切换和取消。`PreloadChecks` 的冷/热像素矩阵覆盖四种渲染档、两种文字渲染/字号配置、两档单篇缩放，以及长密集行、源代码、混合块和空行；截图前完成布局，且每个热样本都断言实际 artifact 命中。

真实 Host 的首次显示检查覆盖左右边缘、两种卡片尺寸和两档缩放。排版 worker 检查覆盖四个 DPI 参数、冻结结果、优先级、同请求合并、取消、释放，以及 worker 被阻塞时实际宿主动画仍可完成。DPI 参数检查不冒充多显示器硬件自动化。

性能探针 `--preload-profile` / `--reverse` 在同一程序里比较不预热、仅行内准备及 artifact 预热；每个样本输出实际命中计数，正文就绪不再依靠“存在子控件”判定。`--preload-memory` 测量托管存活堆增量，不是工作集或原生/GPU 内存。

## #251 收口验证与实测

[Windows 验证运行 34675779886](https://github.com/snownico0722/PaperTodo/actions/runs/34675779886) 测试了最终产品修改并推送为 `3d70b13428c1caa7727a7fbf8fac37fc91c3f50a`。七组 Release 检查（EdgePreview、MarkdownSemantic、MarkdownEditing、TodoNavigation、EdgeTitle、Threading、Persistence）和 Debug EdgePreview 全部通过；Release 与 Debug 的冷/热像素对照均为 **80/80 字节一致，最大通道差 0**，没有放宽原有像素断言。该运行不代替最终清理后的普通 Release CI。

同一 Windows runner、真实 Host/Presenter、460×410 卡片、160ms 动画；正反策略顺序分别运行新进程，每场景/策略各 9 次，剔除各自前 2 次后合计 14 个样本。下表是正文**布局就绪**中位数（ms），不是 GPU 呈现或端到端指针响应时间：

| 场景 | 模式 | 不预热 | 仅行内准备 | artifact 命中 |
|---|---|---:|---:|---:|
| 普通多行（含少量样式） | 增强 | 32.09 | 35.40 | 1.75 |
| 普通多行（含少量样式） | 完全渲染 | 14.04 | 17.09 | 1.15 |
| 密集长行 | 增强 | 86.38 | 74.61 | 2.89 |
| 密集长行 | 完全渲染 | 79.73 | 77.61 | 2.39 |
| 短密集多行 | 增强 | 38.73 | 42.14 | 1.40 |
| 短密集多行 | 完全渲染 | 39.30 | 39.15 | 1.13 |

全部 108 个 `layout` 原始样本（包含前两次）均为实际 artifact 命中；`cold`/`text` 未命中。该实验人为先完成预热，因此证明命中收益，不是自然使用命中率，也不证明 240Hz 始终无掉帧。各场景预热墙钟中位数约 40–112ms，包含等待与调度；工作被前移，没有消失。仅行内准备在少数场景的中位数反而稍慢，不能把几毫秒的差别当作稳定收益。

同一 runner 的独立进程分别测量 #249 `2ad8ece9` 和最终 #251；输入都是 100 张各 6000 字符的重样式 Note。完整 GC 后，摘要/语义增量均约 6.23MiB；额外的 100 份排版结果与该阶段 WPF 缓存从 **105.49MiB 降到 92.57MiB**，减少约 12.92MiB（12.2%）。这是相同压力输入的托管存活堆增量，不是工作集、原生/GPU 内存或所有输入的上界。结果不支持“artifact 带来数量级内存下降”；采用这条路线主要是保持预排版命中、移除隐藏 UI 树及其独占移交，并让输入继续由原生控件处理。

## #246 阶段的历史审查验证

[Windows 审查运行 34647584124](https://github.com/snownico0722/PaperTodo/actions/runs/34647584124) 的七组 Release 检查（EdgePreview、MarkdownSemantic、MarkdownEditing、TodoNavigation、EdgeTitle、Threading、Persistence）及 Debug 预览检查全部通过。运行产出的实际受测源码 blob 用于审查提交；最终分支的普通 CI 另行复验。

`PreloadAuditChecks` 验证三档模式下严格字符/样式边界、语法符号与长链接目标不误计、嵌套样式覆盖不重复、Off 分支、延后读取、无鼠标的启动式预热、相同摘要复用、撤销后的迟到归还拒绝、当前任务打断后续做、新请求的 500ms 合并延迟、单个目标异常不阻断其它目标，以及轻内容不保留缓存。启动式检查使用实际 WPF 窗口和预热队列，不冒充完整 AppController、多显示器开机恢复的自动化端到端测试。

`PreloadChecks` 保留跨视图 A→B→A 实际命中、缓存与重建像素、内容/版本/颜色/尺寸/缩放/模式/DPI 失效、取消、迟到发布、不按数量淘汰与清理检查。该历史版本24组冷/热画面对照在 Release 与 Debug 中均为字节完全一致。三条条件是 OR：在单独验证 100 字符或三个片段边界时，测试输入必须同时避开其它触发条件。

```powershell
dotnet run --project tests/PaperTodo.EdgePreviewChecks -c Release
dotnet run --project tests/PaperTodo.EdgePreviewChecks -c Debug
dotnet run --project tests/PaperTodo.EdgePreviewChecks -c Release -- --preload-profile
dotnet run --project tests/PaperTodo.EdgePreviewChecks -c Release -- --preload-profile --reverse
dotnet run --project tests/PaperTodo.EdgePreviewChecks -c Release -- --preload-memory
```

`text` 仅是探针直接调用的对照策略，产品没有单独的预解析任务队列。性能、像素测试不替代真实混合 DPI、鼠标/键盘和 GPU 呈现验证。
