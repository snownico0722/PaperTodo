# 边缘预览预热检查

本功能建立在 #245 的文字预览实现上。正式职责和 ownership 见 [ARCHITECTURE](../../doc/ARCHITECTURE.md) 的「内置笔记的边缘预览」。本文件只记录可执行检查和历史实验口径，不是另一份架构或发布批准。

## 当前规则

只为存活、可见、实际属于边缘胶囊队列的内置 Markdown Note 排队；要求胶囊模式、边缘胶囊及悬停预览开启。分类只看前 16 块 / 6000 字符的有界摘要，满足任意一条：

- 总源字符数 >400；
- 总源字符数 >200 且样式/链接覆盖字符 >100；
- 总源字符数 >200 且样式/链接片段 >3。

所有比较都是严格大于。总源字符数取摘要各行长度之和，不额外计入换行；样式覆盖和片段按去掉语法标记后的语义内容计算，不把增强模式的 `**`、标签或链接目标重复当成样式片段。嵌套样式不会重复累计同一个字符。围栏内非空正文行按代码样式计数。Off 模式只启用总字符数规则。当前仍是有限预览适配，不扩展块级语义合同。

启动恢复结束和后续入队、纸片形态或内容变化只提交最新的延后读取请求；包括分类在内的准备工作在共享 **500ms 一次性合并延迟**之后执行。没有新的启动计时器、鼠标邻居预测或产品预解析队列。WPF 的 ContextIdle 是低优先级，不代表系统 CPU 已完全空闲，也不保证不可抢占的单次工作段不会影响呈现。

每个合格来源最多保留一份未挂载的当前正文，不按固定张数淘汰。正式悬停优先，被打断但仍有效的请求保留并重新排队；新请求不能被旧任务的完成回调删除，也不能绕过新的合并延迟。永久不符合条件、失败或暂时不能承载的目标不持续轮询，后续正常生命周期事件可以重新提交。

缓存与实际视图之间转移正文的唯一 ownership。内容版本、摘要、排版尺寸、DPI、字体、显示模式和资源不符时拒绝复用；关闭、移出队列或清空缓存后，旧任务不能把已撤销的正文重新存回。启动或修改后立即打开仍可未命中，并走正常分批准备。

## 本轮审查验证

[Windows 审查运行 34647584124](https://github.com/snownico0722/PaperTodo/actions/runs/34647584124) 的七组 Release 检查（EdgePreview、MarkdownSemantic、MarkdownEditing、TodoNavigation、EdgeTitle、Threading、Persistence）及 Debug 预览检查全部通过。运行产出的实际受测源码 blob 用于审查提交；最终分支的普通 CI 另行复验。

`PreloadAuditChecks` 验证三档模式下严格字符/样式边界、语法符号与长链接目标不误计、嵌套样式覆盖不重复、Off 分支、延后读取、无鼠标的启动式预热、相同摘要复用、撤销后的迟到归还拒绝、当前任务打断后续做、新请求的 500ms 合并延迟、单个目标异常不阻断其它目标，以及轻内容不保留缓存。启动式检查使用实际 WPF 窗口和预热队列，不冒充完整 AppController、多显示器开机恢复的自动化端到端测试。

`PreloadChecks` 保留跨视图 A→B→A 实际命中、缓存与重建像素、内容/版本/颜色/尺寸/缩放/模式/DPI 失效、取消、迟到发布、不按数量淘汰与清理检查。本轮24组冷/热画面对照在 Release 与 Debug 中均为字节完全一致。三条条件是 OR：在单独验证 100 字符或三个片段边界时，测试输入必须同时避开其它触发条件。

```powershell
dotnet run --project tests/PaperTodo.EdgePreviewChecks -c Release
dotnet run --project tests/PaperTodo.EdgePreviewChecks -c Debug
dotnet run --project tests/PaperTodo.EdgePreviewChecks -c Release -- --preload-profile
dotnet run --project tests/PaperTodo.EdgePreviewChecks -c Release -- --preload-profile --reverse
dotnet run --project tests/PaperTodo.EdgePreviewChecks -c Release -- --preload-memory
```

`text` 仅是探针直接调用的对照策略，产品没有单独的预解析任务队列。性能、像素测试不替代真实混合 DPI、鼠标/键盘和 GPU 呈现验证。

## 历史性能数据：不是新门槛的重新测量

运行 [34644485740](https://github.com/snownico0722/PaperTodo/actions/runs/34644485740) 使用旧的单行负载门槛。同一 Windows runner、真实 Host/Presenter、460×410 卡片、160ms 动画；正反策略顺序，每策略/场景合计14个去掉预热后的新视图样本。以下是正文布局就绪中位数（ms），不是 GPU 呈现时间：

| 场景 | 模式 | 不预热 | 仅预解析 | 完整排版命中 |
|---|---|---:|---:|---:|
| 普通短行 | 增强 | 45.85 | 38.92 | 旧规则拒绝，0 hit |
| 普通短行 | 完全渲染 | 24.72 | 16.92 | 旧规则拒绝，0 hit |
| 密集长行 | 增强 | 110.96 | 99.32 | 2.60 |
| 密集长行 | 完全渲染 | 101.42 | 89.41 | 1.28 |
| 短密集多行 | 增强 | 56.30 | 44.58 | 1.45 |
| 短密集多行 | 完全渲染 | 45.86 | 27.69 | 1.18 |

该实验先完成预排版再打开，证明命中路径的收益，不证明实际使用的命中率。预排版耗时约27–101ms，包含协作等待，工作并未消失。按现在的总字数/样式规则，旧的部分普通短行样本已可预热；不能继续把“普通短行一定0 hit”当作当前结论，也不能把旧数据标成审查修复后的性能数字。
