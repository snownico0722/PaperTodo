# user.json / Good Lock 系统性测试

PR #451 合入前专项验证。用户要求先保留测试，即使未发现问题，也等合入主线前再讨论取舍；一次通过不构成删除测试的理由。

## 运行

```powershell
# 全参数契约：不需要 Windows 桌面
dotnet run --project tests/PaperTodo.UserInjectionChecks -c Release -p:InjectionSystemChecks=true

# 真实窗口、插件和进程重启：Windows 交互桌面
dotnet run --project tests/PaperTodo.SettingsApiChecks -c Release -p:InjectionSystemChecks=true

# 原生鼠标与键盘用户操作链：同一桌面内串行运行，避免其他操作抢占焦点
dotnet run --project tests/PaperTodo.SettingsApiChecks -c Release -p:InjectionSystemChecks=true -- --user-journeys
```

复用既有测试项目。`InjectionSystemChecks` 只选择测试入口，不改变主程序实现；未指定时仍运行原来的精简回归。`User injection system checks` 工作流执行所有三层测试。

## 第一层：全参数契约

直接编译生产注入源文件，逐项核对注册键、类型、默认值、单位、生效时机、建议范围、机器目录及双语说明。覆盖外部编辑不自动采用、Apply、重复应用、启动采用、删除覆盖、显式默认值仍算覆盖，以及全部动态参数恢复变化中的公式输入。

输入验证包含非法类型、整数溢出、非有限浮点、损坏 JSON、BOM、注释、尾逗号、重复键、未知嵌套数据和格式保留。独立维护请求、绑定、已采用和已接受的重启目标，执行 300 步固定随机种子的编辑/应用/启动/清空/刷新失败状态机。建议范围仍是建议，不为测试添加强制限幅或配置回滚。

## 第二层：窗口与宿主集成

普通窗口与边缘模式各运行 10 个独立场景：实际定时器更新与恢复；五档共 90 个实际悬停缓存字段；字体改变后保留编辑器、正文、选区及撤销；普通设置完全/部分覆盖的锁定；菜单重开；新建尺寸；重启生效时机；Good Lock 草稿、建议、重置与外部冲突；工作线程调度与失效插件租约；退出保存失败时取消重启；真正启动后继进程并返回纸片。

Good Lock 使用实际 XAML 视图和宿主 API。阶段性集成检查可以直接触发控件事件；第三层则必须经过原生输入和实际业务结果，不能把调用处理器或读取槽位当成用户操作。

## 第三层：原生用户行为链

通过 `SendInput` 发送 Windows 鼠标/键盘事件。点击前核对控件布局、WPF 鼠标状态及 `WindowFromPoint` 返回的实际 HWND；输入送达但业务结果不正确仍算失败。

| 场景 | 验证链 |
| --- | --- |
| `user-editor` | 写入实际 user.json → 原生点击 Good Lock 应用 → Ctrl+A/Ctrl+V 编辑笔记 → 核对字号与自动写盘 → 移除覆盖并应用 → 原生撤销/重做，正文与保存正常。 |
| `user-paste` | 先运行无覆盖基线，再将待办批量上限设为 2、3、1，最后移除覆盖 → 每次真实粘贴四行 → 检查截断提示中的实际上限并原生点击确定 → 核对模型、可见行、内容及顺序 → 一次 Ctrl+Z 恢复整次操作。超过上限的提示是正常产品行为，不能在提示仍打开时把撤销失败归为业务故障。 |
| `user-drag` | 默认、关闭拖动自动滚动、移除覆盖三个阶段 → 鼠标按住真实拖动把手、越过阈值并移至视口底部 → 检查实际滚动偏移与捕获 → 松开后排序改变、条目与正文保留。 |
| `user-preview` | 三个实际进程：原值 → 修改后快速重启 → 移除覆盖后再次快速重启。每阶段原生悬停笔记/待办、转移预览 owner、点击勾选框并再次恢复；核对实际行数、渲染宽度、卡片尺寸和队列位置。重启前另核对尺寸仍为旧值，live 间距与跨胶囊驻留已经改变。 |

粘贴后，模型更新早于异步布局和焦点交接。测试等待最后一项真正获得键盘焦点后才发送一次撤销；不手动强行切焦点，也不反复按撤销来掩盖错误，并记录撤销前后的内容。

编辑、粘贴和拖动分别在普通/边缘配置运行。预览需要边缘模式：日志中的 `normal/user-preview` 使用左边缘，`edge/user-preview` 使用右边缘，不表示普通胶囊支持预览。后继进程读取同一隔离数据与配置，不用进程内 `LoadStartup` 冒充重启。

每个场景使用带标识的临时目录和独立进程，不加载用户实际纸片或插件数据。发生失败后继续收集其他场景，最终任何失败仍使任务失败；没有跳过失败场景的通过模式。收尾释放原生按键和鼠标按住状态。

环境变量 `PAPERTODO_INJECTION_EVIDENCE` 指定实际 WPF 视图渲染图像的保存目录。CI 上传 `injection-journey-evidence`；这些图像可核对内容和布局，但不是物理屏幕截图或 DWM 合成证据。实际运行结果、修复前失败和修复后复测记录在 PR 及对应 CI 日志中。

## 验证边界

全参数契约不等于穷尽所有取值组合，也不等于每个参数都完成原生手势测试。关键用户行为链与原有综合 CI 共同验证编辑、持久化、预览、窗口生命周期和材质，不能据此保证任意自定义数值都安全。

Good Lock 的标题等外围回调及会话激活通知由 fixture 提供。重启保留生产 App 的退出/重启实现，但启动由 fixture 接管以隔离数据，不获取桌面全局单实例锁。JSON 编辑阶段直接写入实际文件，没有自动操作用户安装的外部编辑器。系统文件关联、首次选择应用、“另存为”对话框、不同物理屏幕/混合 DPI/显卡上的视觉体验仍需人工验收。

可选微基准：

```powershell
dotnet run --project tests/PaperTodo.UserInjectionChecks -c Release -p:InjectionSystemChecks=false -- --benchmark
```

微基准只观察稳定热循环，不包含启动、JSON、文件 I/O、WPF 或整机性能；不设不稳定的 CI 时间阈值，不据此声称整个功能零开销。
