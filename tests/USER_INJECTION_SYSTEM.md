# user.json / Good Lock 系统性测试

PR #451 合入前的专项验证。用户明确要求先保留测试，即使没有发现问题，也等合入主线前再讨论取舍；不得把一次通过当作自动删除测试的理由。

## 运行

全参数契约检查（不需要 Windows 桌面）：

```powershell
dotnet run --project tests/PaperTodo.UserInjectionChecks -c Release -p:InjectionSystemChecks=true
```

真实窗口、Good Lock 与进程重启检查（Windows 交互桌面）：

```powershell
dotnet run --project tests/PaperTodo.SettingsApiChecks -c Release -p:InjectionSystemChecks=true
```

两条入口复用既有测试项目。参数 `InjectionSystemChecks` 只选择测试入口，不改变主程序实现；未指定时仍运行原来的精简回归。GitHub Actions 的 `User injection system checks` 自动执行两层验证。

## 覆盖范围

| 层次 | 实际验证 |
| --- | --- |
| 注册与目录 | 对实际注册字段逐项核对机器目录、类型、默认值、单位、生效时机、建议范围与中英文说明。 |
| 全参数生命周期 | 外部编辑只改变请求值；Apply、无变化重复应用、启动、删除覆盖、显式默认值均按约定绑定。动态参数删除覆盖后继续使用变化中的原公式输入。 |
| 输入和文件 | 非法类型、整数溢出、非有限浮点、损坏 JSON、BOM、注释、尾逗号、重复键、未知嵌套数据、格式保留、revision 冲突和 reset/remove/set 顺序。建议范围不是强制限制，不把有意允许的越界配置改成限幅。 |
| 状态机 | 300 步固定随机种子的外部修改、应用、启动、清空与刷新失败；独立记录请求、绑定、已采用及已接受的重启目标，逐步核对状态。 |
| 实际消费者 | 五个现存定时器的更新/复原；五档悬停配置共 90 个实际缓存字段的默认值、热更新、档位隔离及移除复原；笔记字体变化后仍保留编辑器、正文草稿、选区和撤销栈。 |
| 设置与菜单 | 单项完全覆盖只读、复合设置部分覆盖仍可写、需重启项目的锁定时机；已有菜单重开时采用下一次使用参数，纸片与边缘入口独立。 |
| 新建与重启时机 | 新纸片真实窗口采用初始尺寸但不改旧纸片；需重启参数不会提前泄漏到新建编辑器。 |
| Good Lock | 实际 XAML 视图和宿主 API：状态显示、外部 Apply 保留格式、单项重置草稿、会话重建后恢复草稿、建议先进入草稿、全体重置、未知键保留、真实冲突提示及用户再次应用。 |
| 插件边界 | 工作线程调用通过 Dispatcher 到达实际 owner；主体与后台 Runtime 使用同一路径；失效租约不能读写或重启。 |
| 退出与重启 | 主文件被占用时退出失败，保留编辑器并取消重启；真正启动第二个进程，检查正常退出保存正文、启动采用 restart 参数、返回指定纸片。 |

窗口层在普通与边缘两种配置下分别运行，每个场景使用独立进程和带标识的临时目录，不使用真实用户的 data.json、插件或 user.json。发生失败时继续执行其他场景，最终汇总失败；任何失败都不能以“继续运行”当作通过。

## 结论边界

全参数契约通过不等于穷尽了 434 个参数的所有取值组合。窗口层验证了真实控件和关键消费者，已有综合 CI 继续验证编辑、预览、持久化、窗口生命周期与材质行为。专项测试不替代不同物理显示器、混合 DPI、显卡驱动及完整视觉体验的人工作业。

Good Lock 测试加载真实插件视图、调用真实宿主注入 API；测试视图的标题等外围回调由 fixture 提供。重启测试保留生产 App 的退出/重启实现，由 fixture 接管启动与数据隔离，不获取用户桌面的单实例锁。外部 JSON 编辑器的系统关联、首次选择应用及“另存为”系统文件对话框仍需人工验收，不能宣称已经覆盖。

可选微基准仍可独立运行：

```powershell
dotnet run --project tests/PaperTodo.UserInjectionChecks -c Release -p:InjectionSystemChecks=false -- --benchmark
```

微基准只观察稳定热循环，不包含启动、JSON、文件 I/O、WPF 与整机性能；不设不稳定的 CI 时间阈值，也不能据此声称整个功能“零开销”。
