# PaperTodo Workbench：对象连续性优先的工作环境

> 本文定义独立于 PR #370 的产品方向。它不是对自由画布增加功能，也不把 PR #370 作为实现基础。

## 为什么另起方向

PR #370 的主要交互模型是全屏自由画布：卡片、节点、拖动、缩放、平移与连线。它回答的是“如何在一个无限空间中摆放纸片”。

Workbench 要回答的是另一件事：**同一批 Paper 如何在轻量桌面和复杂工作之间保持连续，不要求用户记住每种模式各自拥有哪份状态。**

因此 Workbench 不以画布作为唯一主界面，也不把自由摆放当作主要价值。它是一个桌面遮罩式工作环境，按任务提供不同的组织视图，并始终指向原有 Paper。

## 产品模型

### 1. Paper 是稳定对象，不是 UI 类型

Paper 的 ID、正文、待办状态、图片和现有窗口/胶囊身份保持不变。进入或退出 Workbench 不创建副本、不重建内容对象，也不把 Paper 转换为“星图节点”“绑定纸片”或“工作台卡片”。

### 2. Relation 是一等持久数据

连线不是画布装饰，也不能从当前视图临时推导。关系独立保存，拥有稳定 ID、源对象、目标对象、关系类型与可选属性。隐藏连线只影响呈现，不删除关系。第一版关系类型应克制：related、depends-on、blocks、belongs-to、attached-to-context。窗口绑定优先映射现有能力，不另造一套竞争状态。

### 3. Scene 是用户的工作情境

Scene 保存一组 Paper ID 和视图偏好，不拥有 Paper 内容。一个 Paper 可以出现在多个 Scene。删除 Scene 不删除 Paper，也不自动删除它们的关系。

### 4. Projection 是场景内的呈现状态

桌面几何继续由现有 X/Y/Width/Height 与窗口/胶囊生命周期负责。Workbench 的星图坐标、分组、缩放、视图筛选等属于独立的 Scene projection。不同投影不得互相覆盖。

### 5. 临时交互与持久状态分离

选择、悬停、拖拽预览、菜单、临时搜索条件属于瞬时 UI。只有用户可合理期待下次回来仍存在的布局、关系、Scene 与当前工作位置才持久化。

## 工作台不是一个更大的便签桌面

Workbench 以覆盖主显示器的工作环境进入，背景桌面被柔和压暗，用户仍能理解自己没有切换到另一款应用。退出时撤掉遮罩，原纸片仍在原处。

首个纵切片只实现三种组织方式：

- **关系视图**：围绕选中 Paper 展示其持久关联与上下文，不要求所有对象都在自由画布中。
- **任务视图**：把现有 Todo 内容按任务状态组织，所有勾选与编辑仍写回原对象。
- **对象/上下文视图**：以列表和检查器呈现当前 Scene 的对象、文件与窗口关联，优先解决“我在处理什么、它和什么有关”。

星图可以是关系视图的一种投影，但不是唯一入口，也不是工作台的全部。第一版不追求通用无限画布、任意 Widget、插件市场、复杂 AI 代理或替代窗口管理器。

## 交互原则

- 从 Paper 进入 Workbench 时，聚焦同一 Paper；从 Workbench 退出时，不做隐式布局迁移。
- 视图切换不自动重排其他视图；自动整理必须是显式命令，不能覆盖用户手工布局。
- 关系在桌面上可以只显示轻量关联标记；点击标记能回到相关 Scene/关系视图。
- 绑定是附着关系与响应策略，不是模式开关。解除绑定只移除该关系，不更改 Paper 类型、位置或正文。
- 工作台的复杂度通过侧栏、检查器与视图承载，不把桌面纸片塞满工具栏。
- 所有操作必须有可预测的保存语义；保存失败不能展示成功状态。

## 数据与迁移约束

- 不将 PR #370 的 WorkspaceX/WorkspaceY 直接当作 Workbench 的数据模型。
- 在确认现有 AppState / PaperData 的序列化、保存节流、旧数据兼容与测试契约前，不直接添加大批可选字段。
- 新增关系与 Scene 数据应拥有稳定 ID、显式 schema/version、加载归一化、重复/悬空引用处理和旧数据零迁移策略。
- 关系删除、Scene 删除与 Paper 删除的语义必须分别定义；不得因删除一个视图或场景而误删内容。
- 保存失败和退出路径复用既有 StateStore 写入契约，不新建旁路文件后假定跨文件事务成功。

## 实施切片

1. **契约与模型**：定义 Relation、Scene、Projection 的归属与序列化/迁移规则；补齐纯函数测试。
2. **最小工作环境**：实现遮罩窗口、焦点与退出边界，保证不破坏现有 Paper HWND、Edge Capsule、全屏避让和多屏/DPI 逻辑。
3. **对象检查器**：接入现有 Paper 数据，只读呈现关联与上下文；验证对象连续性。
4. **持久关系**：提供明确的创建/删除关系交互，保存并重启恢复。
5. **多视图**：先关系视图与任务视图，再加独立投影持久化。
6. **回归**：覆盖桌面位置、胶囊、窗口绑定、编辑状态、保存失败、旧数据、重启和多显示器。

## 不变量与验收

- 同一 Paper 在桌面、胶囊、关系视图和任务视图中的 ID 始终相同。
- 退出/重进或重启后，关系和 Scene projection 恢复。
- 星图移动不改变桌面 X/Y/Width/Height；桌面拖动不改变 Scene projection。
- 隐藏关系线不删除关系；删除关系在所有视图同步反映。
- 一个 Paper 被多个 Scene 引用时，删除一个 Scene 不删除 Paper。
- 绑定/解绑不改变 Paper 类型、内容或胶囊身份。
- 工作台关闭或异常退出不会覆盖其他视图的布局，也不会让旧窗口事件写入已切换的状态。
- 在可用 Windows 环境中完成 Release build 和相关回归后，才可报告通过；API 写入成功不能替代运行验证。

## 与 PR #370 的关系

PR #370 保持为自由画布路线的独立方案。本设计不复用它的全屏画布窗口作为底座，也不将两套交互强行合并。若本方案获认可，应按上述切片单独实现；之后再基于实际体验决定自由画布是否作为一个可选投影存在。
